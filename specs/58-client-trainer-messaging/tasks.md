# Tasks: Client and trainer exchange messages

**Input**: `specs/58-client-trainer-messaging/` (spec.md, plan.md, research.md, data-model.md, contracts/api.md, quickstart.md)

**Tests**: Required by the Definition of Done (`CLAUDE.md`) and principle V. Tests sit in the same phase as the code they cover.

**Organization**: Phases follow the GitHub tasks, not the spec's user stories, because the story is one pull request with one commit per task (`CLAUDE.md`, Workflow). #59 builds the model (US3, US4), #60 the API (US1 to US4), #61 the client screen (US1, US3), #62 the trainer screen (US2, US3). Story labels show which spec story a task serves. A commit is made only when the user agrees, after the quality gate of every side touched passes.

**Paths**: `B` = `backend/src/main/java/com/kinetiq/messaging`, `BT` = `backend/src/test/java/com/kinetiq/messaging`, `F` = `frontend/src`, `M` = `frontend/src/features/messaging`. Backend class names follow `backend/CLAUDE.md` (Naming); copy the shape of the `quiz` and `client` features where a task says "as in".

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 client writes and reads, US2 trainer's list and replies, US3 unread counts, US4 only the two people
